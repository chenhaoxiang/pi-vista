# Explicit actual K1 runner candidate

This slice is an explicit operator child, not a Pi extension or default admission gate.
Source/mock/current SDK setup does not prove actual paired quality. The previous
16-call INVALID trial is never reused. Actual invocation must use retained public
SDK1.0.4, fixed `codex-local-8319/gpt-6.1-sol:max`, accepted subject SHA and history
pins; there is no fallback, silent retry, extra judge or model switch.

## Flow and ownership

1. `stage6-k1-actual.mjs` accepts a closed explicit CLI: SDK root, profile root,
   readonly broker command pin, accepted history reference, existing test-bank
   credential config/service fingerprint, exact subject checkout and harness SHA,
   plus `--allow-live`. Unknown/missing/duplicate options refuse before effects.
2. Fixed source/learning-native/consumer commands run against clean exact
   `846b9a0...8216f3` subject. Native report counters and fixed command admissions
   produce scoped observations. This is not OS/Meta/global guard coverage.
3. The current host environment binding (Node/platform/arch/plan scope) must equal
   the accepted history environment label before the window. Bank I/O is limited
   to baseline/final config GET and the original accepted Stage5 document GET at
   localhost8888 / `pi-vista-local-test-01a114ab`. Counters record requests,
   not completed reads. No retain, recall, reconcile, new namespace,
   bank config change or service restart. Prior saved projections supply the
   expected reference/content only; stored proof/handle/plan is not restored.
4. `prepareK1ActualHistory` creates a new LOCAL library, reads canonical history,
   imports with new run/experience, obtains process-local fresh verifier evidence,
   checks isCurrent/copy rejection, compiles max_items1 and reuses the existing
   history-context bridge. Expiry and shutdown cannot renew current evidence.
5. `runK1Pilot` prepares all eight metadata and genuine arm admissions before
   requests; one existing coordinator owns global16 and per-session2 budget.
   Each row uses a fresh native session. The native factory loads only the
   selected provider through existing readonly credential helpers, in-memory
   catalog/settings/session/resource controls, no default discovery or config shell.
6. The envelope guard counts every pretransport request and requires a matching
   pretransport attempt for each recorded provider request; missing envelope hooks
   cannot be reported as measured. The CLI terminal watchdog starts at the model
   window, not process startup, and preserves a fixed deadline report if graceful
   cleanup does not settle. Baseline/guided share model/thinking/tools/system/task/budget; guided adds the
   actual compiled historical block to its isolated user input, no extra request.
   Strict decision is a tool call, not free text JSON. Tool-batch terminate is
   only a hint; the request cap still prevents a third session request.
7. Actual message_end Usage is summed, optional reasoning preserved, and the
   delivered metric adapter feeds the unchanged paired validator/aggregator.
   Missing Usage/identity/trace/decision, provider/cancellation/resource/profile
   uncertainty remains unknown, never zero-filled. Model errors stop the window,
   semantic mismatches remain measured failures rather than green success.

## Source/mock boundaries

Imports do no configuration/network/model work. Host callbacks are trusted code,
not sandboxed JavaScript. Freshness belongs to the real LOCAL verifier, not the
copyable facts DTO. Profile/provenance are bracketed by the whole coordinator and
read-only rechecked before rows/finalization. Guard scope is fixed subject commands
only. Root signed Learning, publication, account/channel/version, default activation,
training/weights and production bank remain outside this candidate.

Current implementation is source/mock pending independent review, exact CI/main,
and an actual bounded window. New tests verify new identities, copied proof/verifier
rejection, history/source/policy/env mismatch, native expiry, zero-read hostile input,
single-window8×2 mock execution, semantic mismatch vs provider unknown, Usage and
inert imports. Source/consumer/actual Node20 gates are separate library evidence;
Node20 does not execute public1.0.4 SDK (engine >=22.19).
