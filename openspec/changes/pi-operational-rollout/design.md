# Contracts and stage gates

## Stage1 isolated actual session
Use public pinned Pi SDK1.0.4 on actual Node26 (SDK requires>=22.19); create real AgentSession with explicit model/runtime, in-memory settings/session, independently private agentDir, projectTrusted:false and a host-owned public ResourceLoader/Extension contract implementation. No default package resolver/HOME/ancestor/context/MCP/resource discovery is invoked; only the explicit in-process trusted canary factory is constructed, and real SDK session.reload drives fresh observer construction. Supply only explicitly allowlisted fixture tools, no general shell/write/host access. Fixed synthetic tasks run on actual approved model; raw prompt/output/history/tool bodies remain in-memory SDK data, never Vista events/checkpoints/reports. Observe metadata only.
Actual phases: startup/normal task, nested parallel fixture calls, abort during a waiting tool, subsequent run, public reload with newly constructed addon, and awaited public runtime teardown/shutdown. All observer ports are explicitly private test stores or controlled failure ports. Cross-epoch late results, dropped coverage and nonfinal agent_end remain non-authorizing. Core append/readback compares exact redacted event values as an unordered multiset, since concurrent file append order is not a total-order contract. Intentional cancellation may end with SDK error stop only if both the waiting tool signal released and the original model request signal is actually aborted; preserve original stop reason/error category and never count it as task success. Historical previews use explicitly labelled synthetic archives in this stage, not real owner history or bank.

## Readonly approved model access
No private SDK import or global SDK/profile patch. The host snapshots and closes the explicitly designated selected provider/model configuration, then writes only that closed snapshot (no key/broker-command) to a trial-owned private models file and loads it at ModelRuntime construction with initial refresh disabled. No dynamic registerProvider is called, since SDK1.0.4 performs implicit broad availability checks there; arbitrary sampling/header/compat/routing controls and environment expansion reject. Only the exercised openai-responses API is supported. The actual provider onPayload checks final store:false/model/fixed-tools/mapped-effort/latest-task fields before HTTP transport, and effective thinking is observed from session.thinkingLevel or remains not-captured; an app-owned CredentialStore returns only the designated provider's existing API-key credential in memory and refuses environment overlays/writes/delete/OAuth refresh; foreign provider reads are counted and cause rejection. Pinned key-file access uses a private ordinary-file reader, never shell execution. Model catalog storage is in-memory and network refresh off. No dump of provider config/auth/key/header/endpoints; sanitized reports retain provider/model/API/effective thinking, counters, identity digests and failures without raw diagnostics. Static credential mode defaults to refusing commands. The explicitly enabled SHA-pinned broker mode accepts only the designated provider's single canonical private-file cat lookup with restricted path characters; no arbitrary commands/expansion/pipe or write are accepted. It supplies the key only through the SDK's in-memory credential interface and compares private broker-target metadata separately; no key is serialized into the trial models file. Auth/models/settings configuration metadata and broker target must remain unchanged. Full profile metadata comparison (including shared catalog) is preserved even when false; volatile directory/shared-model-cache drift is separately reported with unknown attribution. An invocation-only standard-Node-file-write boundary refuses/counts mutations outside the owned trial after initialization, and any blocked operation rejects acceptance; this is trusted-runtime instrumentation, not a hostile-native/OS sandbox or global actor attribution. These checks do not prove OS sandboxing. Nothing restores exposed/unproven credentials.
